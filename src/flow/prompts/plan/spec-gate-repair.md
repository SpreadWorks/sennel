When `mode` is `repair`, read the version `2` context through its `bundle`. Each entry in `bundle.units` is one indivisible repair unit identified by `entry.unit.id`; selected element IDs identify those units, not array positions. Resolve each entry's range IDs against `bundle.ranges`, any range `sourceId` against `bundle.sources`, its `guardrailIds` against `bundle.guardrails`, and its `rationaleId` against `bundle.rationales`. Match all references by exact ID and read their complete bodies. A range's writability belongs to the unit's range reference; shared tables grant no permission. The findings in `entry.unit` own that unit's explicit allowed targets and operation kinds. Return `spec-gate-repair.json` with version `1`, stage `spec-gate-repair`, the exact `baseRevision`, and one group per selected unit. Do not rewrite the full Spec or edit canonical artifacts.

Repair groups contain exactly `findingIdentities` and `operations`; do not add `unitId` or a group-level reason. For an allowed `edit-text-field`, each operation contains exactly `kind`, `target`, `expectedDigest`, `edits`, and `reason`. Copy the target and original digest from its writable range. Every item in a replacement for `target: { entity: "task", field: "acceptance" }` must be 500 characters or fewer. This limit applies to each acceptance item, not the array. The CLI truncates any overlong item to the first 500 characters before applying the repair and logs the original and retained text; write within the limit so truncation cannot remove part of a criterion.
